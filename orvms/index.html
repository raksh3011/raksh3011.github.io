ORVMS: from risk at sea to delivery commitments

A multi-tenant platform for shipping companies and the Indian Coast Guard. It connects live and synthetic AIS, modelled maritime zones and graded alerts to voyages, customer shipments and SLAs — and runs on free-tier serverless infrastructure.

Quick start & walkthrough

Try it: pick a role

One click on the landing page signs you in; the sandbox password for all accounts is OrvmsDemo-2026. Accounts: operator (shipments & voyages), riskofficer + orgadmin (approval workflow — critical voyages need two people), cg.kochi (Coast Guard case desk), admin (platform console). Synthetic data, held in memory in your tab; it resets on reload. The same code runs on Cloudflare Workers in the full deployment.

Vessel traffic near India is partly synthetic and always labelled; real feeds come from aisstream.io and Digitraffic. Zones are modelled, not official limits. Payments run in a sandbox.

What it does

WhoCapability
OperatorsSupply-chain control tower: live ETA from the vessel's position, delivery risk against the committed date, cargo value passing through risk areas.
Risk officersVoyage planning with automatic route-risk assessment and an approval workflow: low auto-approves, high needs a risk officer, critical needs two people, and the preparer can never approve.
Coast GuardSuspicious-vessel case desk with priority P1–P4, SLA timers, assignment, automatic escalation and post-incident reports.
Org adminsFleet registry with CSV import, plans and quotas, billing with GST invoices, compliance reports, API keys and HMAC-signed webhooks.
Platform ownerOnboarding, revenue and receivables console, operations and health, backups and audit trail.

Architecture

Four-layer design with business rules kept as pure, testable functions.

PresentationTypeScript single-page app, live map and role-based views
APIHono REST + WebSocket, JWT auth, RBAC, tenant isolation
ServicesVoyages, shipments, cases, billing, webhooks, background jobs
DomainRisk engine, scoring, ETA, SLA rules, invoicing — pure functions
  • Real-time path: feed adapters parse, validate, normalise and throttle AIS from WebSocket and REST sources into a Durable Object hub that holds vessel state, runs the risk engine and raises graded alerts.
  • Storage: Cloudflare D1 for business records; the same business API runs against in-memory and SQL storage in tests.
  • Browser demo: the page above is the production UI with the server swapped for the same Hono app and risk engine running in the tab (app.fetch() instead of HTTP, an in-memory repository instead of D1). Roles can be switched live, time can be sped up, and a guided tour and architecture view are built in.
  • Quality: 226 unit and API tests, lint, type-check and CI; OpenAPI spec and written requirements, architecture and tech-decision records.

Tenant isolation

One organisation can never read or change another's data.

Segregation of duties

Preparers cannot approve their own voyages; critical risk needs two approvers.

Zero-cost hosting

Workers + Durable Objects (SQLite) + D1 on the free plan.
